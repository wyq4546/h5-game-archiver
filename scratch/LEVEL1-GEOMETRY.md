# Level 1 真实几何（从 Unity 场景树提取，非猜测）

来源：`scripts/.tmp/level1_tree.json`（agy 用 MainController → levelTf(+0x74) → GetChild → get_name/get_position 递归 dump）
**关键：子节点坐标本来就是世界坐标，不要再加上 Template 的 z**（加了会把 1000 的关卡算成 2010）。

## 1. 轨道结构

- 车道中心 `x ∈ {-4, -2, 0, 2, 4}`，间距 2，瓦片宽 2。
- 瓦片沿 z 大多每 **2** 个单位一块；但有 **跳跃段** 是每 **8** 个单位一块（如 z=894,902,910,918,926,934,942），且 x 交错。
- 全关 z 从 0 到约 1015，Portal 在 z≈1011，`MyLevel.levelLength = 1000` 对得上。
- 障碍物的 x **不一定在车道中心**：有 x=±2、±3、0 各种，所以不能按"道号"判断，必须按实际 x 和宽度算。

## 2. 哪些是地面（可踩）

`Tile_Normal`、`Tile_Fall`、`Tile_Drop`、`DropTiles`、`MovingTiles` 全部是**瓦片**。
`Tile_Fall` / `Tile_Drop` 不是陷阱——z=184 整排 5 道都是 Tile_Fall，如果它致命关卡就不可通过。
`Tile_Fall`"掉落"大概率指"踩上去会下沉/属于浮桥"，仍然可通行。

## 3. 哪些是障碍（挡路）

按出现频次：`Pillar`(97) `Weights`(68) `Pusher`(69) `Hammer`(34) `Weights_WingBody`(34) `Cannon`(10) `Tire`(6) `Tree/树系列`(约 160)

子件不用单独算，它们和父件同 (x,z)：`Cube_005/006/007`、`PBottom`、`Collider`、`Circle_002`、`Cylinder/002`、`Main`、`Empty_001` 都是 `Pillar`/`Hammer` 的组成件。

## 4. 已确认的两个死亡点解释

**z≈130（历史最好成绩 128.8 就死在这）**
```
z=124~128   x = -2, 0, 2, 4 全部有瓦片
z=130       x = 0 有瓦片；x = ±2 有立柱(Pillar)；x = ±4 悬空
```
球在 x=1.85（2 道）→ 撞立柱。**唯一活路是 z=130 时在 x=0**。
而 z=118~122 又只有 x=4 有瓦片（x=0 悬空、x=2 有 Weights）。所以 118 必须在 x=4，130 必须在 x=0，Δx=4 / Δz=12，斜率 0.33，做得到。

**z=52**
```
z=50   x = -4,-2,0,2 有瓦片
z=52   x = 0 有瓦片，但上面正好立着一根 Pillar
z=60   x = -2,0,2 有瓦片
```
z=52 唯一的一块瓦片被立柱占住 → 说明**球必须从 z=50 直接跳到 z=60**（跳过 52~58）。这是个重要事实：不是每一层瓦片都要落，跳跃段的层可以整层略过。

## 5. 物理能力（实测，修正之前的错误结论）

我之前说"|dx/dz| 超过 0.25 就做不到"，**这是错的**。用 212 上的轨迹反推：
```
z 115.08 → 119.56  (Δz=4.48)
x 0.09   → 3.61    (Δx=3.52)
unityTime 12.554 → 12.866 (Δt=0.312s)
→ 前进 14.4 u/s，横移 11.3 u/s，|dx/dz| ≈ 0.79
```
而且 z=16~20 是一道**斜向立柱墙**（x=4→2→0，每 2 个 z 移一道），必须每 2 个 z 横移 2 个 x 单位才能躲开 → 实际需要 **|dx/dz| = 1.0** 才过得去。这个数字要用实跑确认，它是控制环最关键的上限。

## 6. 建议的架构（别再维护固定 waypoint 表）

固定 waypoint 表的问题：`Hammer` 在转、`Weights` 在摆、`Pusher` 会推，时序对不上就必死；而表里写的是"某个 z 时刻该在哪个 x"，一旦球速/起步时刻有偏差就全错位。

改成运行时反应式（60fps 下每帧 16ms，完全够）：
```
每帧:
  lookahead = [z+4, z+16]
  1) 地面检查：当前 x 在 lookahead 内是否连续有瓦片？
     没有 → 不改 x（保持直线，球会自己跳过缺口）
  2) 障碍检查：lookahead 内是否有 obs（|ox - x| < w + margin）？
     有 → 选最近的安全 x，立刻开始横移
  3) 安全 x 的判定：既没有障碍，且在落点 z 有瓦片
```
用 `level1-obstacles.json` 里的 ground/obs/spin/push 四张表做查询（已按 z 排序，二分查找即可）。
